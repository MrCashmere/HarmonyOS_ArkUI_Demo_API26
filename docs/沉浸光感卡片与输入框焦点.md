# 沉浸光感卡片套输入框「点不动」——根因、修法与工程规矩

> **结论先行**：不要把输入框放进沉浸光感卡片容器（`MaterialCard`）。它的外壳带
> `.focusable(false)`，ArkUI 的焦点系统里 **祖先不可获焦 ⇒ 子组件也获不了焦**，
> 表现是"点下去毫无变化、一个字也打不进去"，而且**不报错、不闪退、编译照过、离线门禁照绿**。
>
> 沉浸光感本身**可以继续要** —— 只要材质承载层与输入框是**兄弟**，不是**祖先**。
>
> 本篇只讲机制与规矩，不贴工程源码；涉及的落点一律给到文件与函数名，需要细节请直接看那一行。

---

## 1. 症状：怎么一眼认出是这条坑

| 判据 | 值 |
| --- | --- |
| 界面表现 | 点输入框：**边框不变、光标不出现、键盘不弹** —— 用户原话是"**毫无变化**" |
| 报错 | **没有**。控制台没有、界面没有、崩溃也没有 |
| 编译 | ArkTS 编译通过（`CompileArkTS` / `PackageHap` 全绿） |
| 离线门禁 | 全绿（这类问题只有真机能验） |
| 影响范围 | 同一张卡里的**所有**输入框**同时**坏（它们共用一个外壳） |
| 手动取证 | 调 `FocusController.requestFocus(id)` 会抛 `150002 - This component has an unfocusable ancestor.` |

**"毫无变化"这四个字是钥匙**：它说明**焦点压根没给过去**，而不是"键盘没弹"或"输入法坏了"。

---

## 2. 根因

### 2.1 规则

ArkUI 的焦点系统里，一个组件能不能获焦取决于**它的祖先链**：
祖先 `focusable(false)` ⇒ 后代一律获不了焦。SDK 把这条单列成一个错误码：

```text
FocusController.requestFocus():
@throws { BusinessError } 150002 - This component has an unfocusable ancestor.
```

### 2.2 卡片容器的外壳就是这样一个祖先

`components/MaterialCard.ets` 的 `cardShell()`（两个分支 `cardShell` / `cardShellWithMenu`
属性一致）在**同一个容器节点**上同时挂了：

| 属性 | 作用 | 与这条坑的关系 |
| --- | --- | --- |
| `.focusable(this.cardFocusable)` | 对应 `.focusable()` | **致命的一条**，默认 `false`（`MaterialCard.ets:177`） |
| `.onTouch(...)` | 按压流光跟随手指 | 消费触摸 |
| `.gesture(LongPressGesture...)` | 长按菜单 | 消费手势 |
| `.onClick(...)` | 卡片点击 | 消费点击 |
| `.onAreaChange` / `.hoverEffect` / `.enabled` / `.opacity` | 光斑坐标、悬停、置灰 | 无关 |

⇒ **任何**塞进这张卡的 `TextInput` / `TextArea` 都拿不到焦点。

### 2.3 不是沉浸光感材质的锅（最容易误判的一点）

材质承载层 `MaterialCardLayer` 自己**也是** `Toggle` 载体，且同样
`focusable(false)` + `hitTestBehavior(HitTestMode.None)` + `enabled(false)` ——
但它是**兄弟节点，不是祖先**。结构示意（非源码）：

```text
Stack {
  材质承载层（Toggle + systemMaterial）   ← 兄弟：只画材质，不吃触摸
  Column { 输入框 … }                     ← 兄弟：内容
}
```

⇒ **沉浸光感可以继续用**，只要材质层与输入框**平级**。
真正致命的是外层那张"既是容器、又 `focusable(false)`、还抢触摸"的卡片壳。

> 这条也是当初能定位真因的依据（对照组）：本工程**唯一**在真机上长期可用的输入框 ——
> 首页搜索 `SearchOverlay` 的 `TextInput` —— 恰好**不在**卡片容器里，
> 它旁边同样有一个 `focusable(false)` 的 `Toggle` 装饰层，但那是**兄弟**；
> 而且它靠 `.defaultFocus(true)` 自动获焦。也就是说：
> **那时全工程没有第二处依赖过「点一下获焦」**，所以这条路一直坏着也没人报。

## 3. 修法：焦点三件套（缺一条都可能复发）

| # | 做法 | 为什么 |
| --- | --- | --- |
| ① | **外壳自建**，祖先链上不留不可获焦的组件 | 从根上消除 150002 |
| ② | 输入框 `.id(常量)` | `requestFocus` 只能按 id 定位目标 |
| ③ | 被点到时**显式** `requestFocus`，整段 try 住、失败只记一行日志 | 兜"系统没把焦点给过去"；拿不到焦点绝不许崩页面 |

### 3.1 外壳的两种写法

**A. 要保留沉浸光感（推荐，观感与现成卡片容器完全一致）**

`Stack` 里平铺两层：**材质承载层**（`MaterialCardLayer`，圆角与卡片一致）
+ **内容列**（`Column`，放输入框与按钮）。材质层与输入框是**兄弟**，
所以既保住了光感，又不引入不可获焦的祖先。

- 现役落点：`components/CommentComposer.ets`（评论输入条）、
  `pages/ChatPage.ets` 的 `composer()`（私信输入条）。

**B. 不需要材质（依赖最少）**

自绘一个只保留观感的 `Column`：底色（与 `cardSurface` 同源）/ 毛玻璃 /
圆角 / 描边 / 内边距 —— **不挂** `focusable`、`onClick`、`onTouch`、`gesture`。

- 现役落点：`pages/CdkPage.ets` 的 `CdkInputCard`、
  `foreign/ui/SklandLoginPage.ets` 的 `SklandInputCard`。
- 这两处换壳前本来就走非材质档，所以**观感完全一致**，用户看不出差别。

### 3.2 `requestFocus` 兜底（三件套的第 3 条）

在页面/组件里写一个私有方法：`getUIContext().getFocusController().requestFocus(输入框 id)`，
**整段 try 住**，catch 里只 `Logger.warn` 一行。

⚠️ **失败只记日志、绝不弹窗**：焦点拿不到只该少一次便利，不该让页面崩、
更不该甩一句用户看不懂的错误。四个落点的写法与措辞口径完全一样（只前缀不同）。

### 3.3 `defaultFocus(true)` 什么时候用

只给「**面板一出现就该打字**」的场景（搜索框、登录面板的第一个框）。
兑换码页那种"进来先看空态"的页面**刻意不用** —— 进页就弹键盘是打扰。

### 3.4 为什么不直接把 `cardFocusable` 传 `true`

1. 那条参数是为**可点击 / 可聚焦的卡片**（主题色色块、入口行）准备的，
   不是给"容器里放输入框"准备的；
2. 外壳同时还挂了 `.onTouch`（按压流光）与 `.gesture`（长按），它们要**消费**触摸 ——
   让容器可获焦，等于让"卡片"和"输入框"抢同一个焦点与手势，
   是把一个明坑换成一个更难查的暗坑；
3. 门禁与文档口径已经统一为"含输入框另写外壳"（`docs/UI.md` §10.1 / §12.4），
   改默认值会让既有断言和既有页面一起失准。

## 4. 门禁怎么把它钉住

| 脚本 | 断言要点 |
| --- | --- |
| `scripts/test_foreign_skland.mjs` | 该页 `MaterialCard({` 只剩 **1** 处；本地输入卡外壳体内不出现 `focusable` / `.onClick` / `.onTouch` / `.gesture`；四个输入框都有 `.id(...)`；四个都被点到时显式请求焦点；请求方法走 `getFocusController().requestFocus` 且吞异常 |
| `scripts/tools/verify-community-wiring.mjs` | `CommentComposer.ets` 里**没有** `MaterialCard(`、且**有** `MaterialCardLayer(` |
| `scripts/tools/verify-contract.mjs` | `ChatPage` 的 `composer()` **切片内**没有 `MaterialCard({`、有材质承载层调用；`INPUT_ID` 常量、`.id(INPUT_ID)`、`requestFocus(INPUT_ID)`、失败只 `Logger.warn` 四样齐全 |
| `scripts/test_message_center.mjs` | 同上（镜像一份，与 `verify-contract` 逐字对齐） |

⚠️ **否定断言必须按函数定义切片**：`composer()` 体里本来就含有 `MaterialCardLayer(` 这个名字，
拿整份源码去判"不含 `MaterialCard(`"会**恒红**，而它红起来的样子很像"又套回容器了" ——
**会误导排查方向**。（两个脚本都用 `indexOf('  composer() {')` 起、`'\n  /**'` 止做切片。）

## 5. 新写输入框时的模板与自查

1. **外壳**：要么「材质承载层 + 内容列」平铺，要么自绘干净 `Column`；
   ⛔ **不出现 `MaterialCard({`**。
2. **id**：输入框 `.id(常量)`。
3. **兜底**：点击回调里调一次请求焦点的方法，方法内整段 `try/catch` + `Logger.warn`。
4. **defaultFocus**：只有"出现即打字"才加。
5. **自查命令**（新增 / 改动输入框后跑一遍）：

```bash
grep -rn "MaterialCard(" entry/src/main/ets --include=*.ets
# 逐个确认：这些卡片的内容闭包里有没有 TextInput / TextArea
```
